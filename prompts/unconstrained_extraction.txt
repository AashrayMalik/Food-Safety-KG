## NAMING CONVENTIONS

1. **Entity types**: Use short, descriptive CamelCase names (e.g. ``Food``,
   ``PermissibleLimit``, ``Contaminant``, ``Regulation``).  Do NOT use
   namespace prefixes (no ``fflo:``, ``fkg:``, etc.).

2. **Relations**: Use short, descriptive camelCase verbs or verb phrases
   (e.g. ``hasLimit``, ``appliesTo``, ``foundIn``, ``causes``).  Be
   CONSISTENT — use the same relation name for the same semantic link
   across all triplets.

3. **Entity names**: Use the canonical form as it appears in FSSAI text
   (e.g. "mustard oil", not "mustard"; "chilli powder", not "chillies").

4. **If you've already extracted a relation for one chunk, reuse the same
   name for that relation in subsequent chunks.**  Do not invent aliases.

1. Extract from TARGET CHUNK only. Context chunks are for reference.
2. evidence_span must be a verbatim substring (≤ 12 words).
3. confidence: 0.9-1.0 = explicit, 0.7-0.89 = inferred, 0.5-0.69 = plausible.

4. If a meaningful relation exists but you cannot express it cleanly, output

5. No hallucination. Extract only what is grounded in the evidence_span.
6. Output ONLY valid JSON — no markdown fences, no commentary.
7. Keep total output under 4000 tokens. Max 10 triplets per chunk.
   Keep "notes" under 200 characters.
